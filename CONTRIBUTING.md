# Contributing to opencode-artes

## 🌟 Thank you for contributing!

We love your help adding skills to make the OpenCode agent ecosystem better. Please read these guidelines carefully before submitting a pull request.

## 📁 Folder-First Requirement

**All new skills MUST follow the nested directory layout:**

```
skills/
  <skill-id>/
    <skill-id>.md
```

**Do NOT place `.md` files directly in the root `skills/` directory.**

The `file_path` in your skill's YAML frontmatter must strictly match `skills/<skill-id>/<skill-id>.md`. This is validated by the pre-PR QC step.

## 🛡️ Mandatory Pre-PR QC Step

**Every skill file must pass the Quality Control audit before a PR can be merged.** Run the following check locally before committing:

```bash
# 1. Frontmatter Check
python -c "
import yaml
with open('skills/<skill-id>/<skill-id>.md') as f:
    content = f.read()
if not content.startswith('---'):
    print('FAIL: No YAML frontmatter')
    exit()
# Parse frontmatter
parts = content.split('---')
if len(parts) < 3:
    print('FAIL: Invalid frontmatter structure')
    exit()
ft = parts[1].strip()
for key in ['id', 'name', 'category', 'tags', 'author', 'version', 'description']:
    if key not in ft:
        print(f'FAIL: Missing frontmatter key: {key}')
        exit()
print('PASS: Frontmatter valid')
"

# 2. Path Alignment Check
grep -q 'file_path: skills/' skills/<skill-id>/<skill-id>.md && \
  grep -q "file_path: skills/<skill-id>/<skill-id>.md" skills/<skill-id>/<skill-id>.md && \
  echo 'PASS: file_path aligned' || echo 'FAIL: file_path mismatch'

# 3. Internal References QC
# Check that no stale references to old flat paths exist
if grep -r 'skills/[^/]+\.md' skills/<skill-id>/<skill-id>.md | grep -v '<skill-id>\.md' > /dev/null; then
  echo 'FAIL: Stale cross-references found'
else
  echo 'PASS: No stale references'
fi

# 4. Dry-Run Test (optional but recommended)
npm run build && echo 'PASS: Registry builds successfully'
```

**All three checks must pass** before creating a pull request. If any check fails, fix the issues before committing.

## 📝 Development Workflow

1. **Create a new skill directory**: `mkdir skills/<skill-id>/`
2. **Create the skill file**: `skills/<skill-id>/<skill-id>.md`
3. **Fill in YAML frontmatter** with all required fields:
   - `id`: lowercase hyphenated identifier (e.g., `condition-based-waiting`)
   - `name`: descriptive skill name
   - `category`: one of the established categories
   - `tags`: space‑separated list or YAML array
   - `author`: your name or `opencode-core`
   - `version`: start at `1.0.0`
   - `description`: starts with "Use when..." describing triggering conditions
4. **Write the skill content** following the SKILL.md format specification
5. **Run the QC checks** above
6. **Run `npm run build`** to regenerate `registry.json`
7. **Commit and push** your changes
8. **Submit a PR** with a clear description of the skill's purpose and usage

## 📂 Repository Structure

```
opencode-artes/
├── skills/
│   ├── <skill-id-1>/
│   │   └── <skill-id-1>.md
│   ├── <skill-id-2>/
│   │   └── <skill-id-2>.md
│   └── ... (all skills in nested directories)
├── registry.json    ← auto-generated by npm run build
├── package.json
├── README.md
└── CONTRIBUTING.md
```

## 🎯 Categories

Skills are categorized into the following groups. When creating a new skill, choose the most appropriate category:

- **ai-ops** – LLM workflow orchestration, prompt evaluation, context management
- **algorithms** – Big O analysis, data structure optimization
- **api** – GraphQL, webhooks, REST APIs
- **backend** – Server-side infrastructure, caching, auth, WebSockets
- **cloud** – Terraform, serverless, Kubernetes
- **core-coding** – Design patterns, async concurrency, type systems
- **core-engine-hardening** – Verification, sanitization, context management, dependency mapping
- **database** – SQL, migrations, schema tools
- **developer-experience** – CLI tools, diagrams, documentation, cron scheduling
- **frontend** – Accessibility, SEO, Tailwind, i18n, type definitions
- **orchestrator** – Pipeline deployment, auto-building, iterative fix loops
- **security** – Token rotation, secret detection, leak prevention
- **software-architecture** – Design patterns, dependency injection
- **testing** – Unit tests, test generation, property‑based testing

## 📦 Getting Started as a User

```bash
# Clone and build
git clone https://github.com/RMAzrim/opencode-artes.git
cd opencode-artes
npm run build

# List available skills
node -e "const r = require('./registry.json'); console.log(r.length + ' skills available')"

# Use a skill
opencode skill:run verify-orchestrator
# or browse skills in your IDE
```
